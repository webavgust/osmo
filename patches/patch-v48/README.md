# patch v48 — проект со страницы компании

Ставится поверх v47. «Проект» (модуль DealProject) теперь заводится, отслеживается и закрывается прямо на странице
компании `/companies/detail/{id}` — там, где собираются спецификация, КП и конфигурация. Идти в реестр сделок Битрикса
больше не нужно. Макет одобрен владельцем 06.11.2026 (решения: итог «успешно / нет» + комментарий; закрытие
спецификаций всегда подтверждается вручную; параллельные проекты — это два проекта).

Скриншоты (локальные данные): `company-projects.png`, `company-spec-column.png`.

## Что поменялось

- **Блок «Проекты» на странице компании** (правая колонка, над «Спецификациями»):
  - кнопка «Создать проект», подсказка «N спецификаций без проекта» (только «В процессе», не входящие в действующий проект);
  - карточка проекта: статус (В работе / Закрыт: Успешно|Неуспешно), пилот и срок (просрочен — красным), сумма,
    оплачено и прогресс оплат по валютам, ближайший плановый платёж, спецификации (ссылки на строку таблицы),
    КП и конфигурации, сделки Битрикса; кнопки «Изменить», «Закрыть проект» / «Вернуть в работу»;
  - закрытые проекты свёрнуты под действующими, с комментарием итога.
- **Попап «Новый проект»** (`deal_project.box_company`): дата старта, пилот со сроком, спецификации компании
  (занятые действующим проектом — неактивны), блок «Подтянется само» — сделки Битрикса по цепочке
  спецификация → КП → сделка; сделка, уже прикреплённая к другому проекту, пропускается с предупреждением.
  Проект без сделки допустим. Сделка остаётся за закрытым проектом: новый проект по тем же спецификациям
  (например, после пилота) создаётся без неё, а предупреждение показывается после перезагрузки страницы.
- **Попап «Закрыть проект»** (`deal_project.box_close`): итог «Успешно» / «Неуспешно» (обязательно), комментарий
  (необязательно), список спецификаций проекта с суммой, оплатой, остатком и статусом. Полностью оплаченные отмечены
  заранее, но закрываются только отмеченные вручную. Возврат в работу очищает итог.
- **Попапы «Изменить» и карточка проекта** (из реестра сделок тоже): кнопка «Отправить в архив» заменена на
  «Закрыть проект» — открывает тот же попап с итогом; «Вернуть из архива» → «Вернуть в работу». Карточка проекта
  показывает итог и комментарий к нему.
- **Колонка «Проект»** в таблице спецификаций компании — ссылка на карточку проекта.
- **Блок «Проекты» слева переименован в «Конфигурации»** (это модуль Project: группы конфигураций), подписи попапов
  «Новая группа конфигураций» / «Группа конфигураций».
- **«OSMO AVG» → «OSMO CRM»** в заголовке вкладки, подвале и хлебных крошках (сайт переехал на osmo-crm.ru).
  `APP_NAME` в `.env` не меняется: из него собирается имя cookie сессии.
- Исправлено: `DealProjectService::forDeals($ids)` со списком id всегда возвращал пусто.

## Что сделать руками при выкатке

1. Полная копия БД: `php patches/deploy-v21-v32/backup_db.php /root/backup`.
2. `git pull`, `runuser -u www-root -- php artisan migrate --force`, `runuser -u www-root -- php artisan view:clear`.
3. Проверить, что в `storage` и `bootstrap/cache` нет файлов root.
