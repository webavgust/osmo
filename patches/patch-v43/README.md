# patch v43 — к одной сделке Битрикс24 можно привязать несколько КП

Ставится поверх v42. Решение владельца 08.10.2026: правило «одна сделка — одно КП» (правка 12.09.2026)
отменено. Связь КП ↔ сделки теперь многие-ко-многим: у КП по-прежнему может быть несколько сделок
(одна главная — `is_main`, дублируется в `proposals.crm_deal_id`), и к одной сделке можно прикрепить
несколько КП. Запрета «у КП одна сделка» нет.

Таблица `proposal_crm_deals` уже подходит: `unique(proposal_group, crm_deal_id)`, `index(crm_deal_id)` —
миграции нет. `config/modular.php` не меняется.

## Часть 1 — движок

### Что изменено

**`app/Modules/Pub/Proposal/Services/ProposalDealService.php`**

- `attach()` — убран запрет «Сделка уже привязана к КП …». Привязка к сделке, у которой уже есть КП,
  проходит молча.
- Новые методы (форматы — ниже): `proposalsOfDeal()`, `proposalsByDeal()`, `dealProposalRows()`,
  `proposalRows()`, `cluster()`.
- `proposalOfDeal(int)` оставлен обёрткой «первое из `proposalsOfDeal()`» — для старых вызовов.
- `takenDealIds(?string)` оставлен для совместимости (прежняя форма `[deal_id => Proposal]`, теперь
  первое КП сделки); внутри портала больше не вызывается.
- `search()` — сделки с КП больше не прячутся и не помечаются занятыми; у каждой строки справочно
  список других КП сделки. `only_free` теперь значит «только сделки без КП» и по умолчанию **false**
  (так же по умолчанию в `ProposalBoxController::deal` и `ApiProposalStatusController::dealSearch`).
- `searchProposals()` — новый параметр `deal_id`; в строках `attached_here` и `deals`.
- `check()` — сверка сумм идёт по **кластеру** (см. ниже). Прежние ключи результата сохранены,
  добавлены `own_amount` и `cluster`.
- Комментарии с правилом «один к одному» переписаны.

**`app/Modules/Bitrix/CrmDeal/Controllers/Api/ApiCrmDealController.php`**

- `proposalSearch` передаёт `deal_id`, в строках ответа добавлены `attached_here`, `deals`.
- `proposalAttach` — проверка «Сделка уже привязана к КП» убрана; ответ несёт актуальный список КП сделки.
- `proposalDetach` — отвязывает **конкретное** КП: параметр `proposal_group` в теле запроса
  (URL маршрута прежний: `POST api/crm-deal/proposal/detach/{deal}`). Связь проверяется: если
  этого КП у сделки нет — ошибка «Это КП к сделке не привязано». Переходный режим для старого попапа:
  без `proposal_group` отвязка проходит, только если КП у сделки ровно одно; при нескольких —
  ошибка «К сделке привязано несколько КП — укажите, какое отвязать». Новый шаблон должен слать
  `proposal_group` всегда.

**`app/Modules/Bitrix/CrmDeal/Controllers/CrmDealBoxController.php`** — попап `bitrix/deal/box/proposal/{deal}`
получает `proposals` (все КП сделки) и, для совместимости шаблона до переделки, `proposal` (первое из них);
`rows` ищутся с `deal_id`.

**`app/Modules/Pub/Proposal/Controllers/Api/ApiProposalStatusController.php`** (только `dealSearch`) и
**`ProposalBoxController.php`** (только `deal`) — `only_free` по умолчанию false, в ответе `dealSearch`
поле `proposals`.

### Форматы для шаблонов (часть 2)

Методы `ProposalDealService`:

```php
proposalsOfDeal(int $dealId): Collection<Proposal>
// последние итерации всех КП сделки; порядок: sended_at desc (без даты — в конце), затем number, id

proposalOfDeal(int $deal_id): ?Proposal            // = proposalsOfDeal()->first()

proposalsByDeal(?string $exceptGroup = null, ?array $dealIds = null): Collection
// [deal_id => Collection<Proposal>] — КП сделок без $exceptGroup; порядок внутри — как в proposalsOfDeal()

dealProposalRows(int $dealId): array
// [{group, number, name, url, is_main}] — все КП сделки; is_main: эта сделка — главная у КП

proposalRows($proposals): array                    // [{group, number, name, url}]

cluster(string $group, int $maxGroups = 30): array
// ['groups' => [group, ...] (первая — исходная), 'deal_ids' => [int, ...] (по возрастанию), 'truncated' => bool]
```

`search()` — у каждой строки-сделки:

- `proposals` — другие КП сделки (без текущего КП попапа): `[{group, number, name, url}]`, пустой массив — КП нет;
- `is_taken` всегда `false`, `taken_by` всегда `null` — оставлены, чтобы старый `deal_rows.blade.php`
  не прятал кнопку «Привязать». В новом шаблоне их не использовать.

`GET api/proposal/deal/search/{proposal}` (`ApiProposalStatusController::dealSearch`) — строки как раньше
(`id, title, company, customer, manager, stage, amount, currency, quarter, is_taken, taken_by`) плюс
`proposals: [{group, number, name, url}]`. Параметр `only_free=1` — только сделки без КП.

`searchProposals(['deal_id' => …])` и `GET api/crm-deal/proposal/search/{deal}` — в каждой строке:

- `deals_count` — всего сделок у КП (как раньше);
- `attached_here` — bool, КП уже привязано к этой сделке;
- `deals` — ID **других** сделок КП (без этой), по возрастанию, например `[223, 717]`.

`POST api/crm-deal/proposal/attach/{deal}` (`proposal_group`) и
`POST api/crm-deal/proposal/detach/{deal}` (`proposal_group`):

```json
{"result": "success", "message": "Сделка привязана к КП AK727",
 "proposals": [{"group": "…", "number": "AA796", "name": "…", "url": "…", "is_main": true},
               {"group": "…", "number": "AK727", "name": "…", "url": "…", "is_main": false}]}
```

`proposals` — КП сделки после операции (для перерисовки попапа без закрытия). Ошибка — `{"result": "error", "message": "…"}`.

Попап `bitrix.deal.box.proposal` получает `$proposals` (Collection<Proposal>) и `$proposal` (первое или null);
у строк `$rows` есть `attached_here` и `deals`.

### Сверка сумм: кластер

Кластер — связная компонента графа КП↔сделки: от группы КП обход по `proposal_crm_deals`
(КП → его сделки → их КП → …), не больше 30 групп (`truncated`). Если кластер — одно КП, `check()`
считает ровно как раньше по переданным `$links`. Если КП несколько:

- `deals_amount` — сумма **уникальных** сделок кластера (общая сделка считается один раз);
- `amount` — сумма последних вариантов всех КП кластера, `own_amount` — только этого КП;
- `errors` — по всем сделкам кластера (ключ — deal_id, в том числе сделки других КП);
  текст расхождения: «Сумма сделок X ≠ сумме КП AA796 + AK727 Y (расхождение Z)»;
- `summary` при совпадении: «Суммы сходятся: Y RUB (вместе с КП AK727)».

Новый ключ результата:

```php
'cluster' => [
    'shared' => bool,            // в кластере больше одного КП
    'groups' => [group, ...],
    'proposals' => [{group, number, name, url, currency, amount}, ...],  // первое — это КП
    'others' => [...],           // те же строки без этого КП — для «сделка общая с КП …»
    'deal_ids' => [int, ...],
    'truncated' => bool,
]
```

Валюта сверяется с валютой этого КП; суммы КП кластера складываются без пересчёта курса.

### Скрипт sync_main

`patches/patch-v43/tools/sync_main.php` — однократная починка: у части КП главная привязка в
`proposal_crm_deals` есть, а `proposals.crm_deal_id` пуст (скрипты 23.09 создавали привязки без `syncMain`).
Для каждой группы с привязками, где дубль расходится, делает то же, что `ProposalDealService::syncMain()`,
но **не сдвигает `proposals.updated_at`** и не пишет журнал изменений. КП без привязок не трогает.

```bash
php patches/patch-v43/tools/sync_main.php --dry-run   # посчитать
php patches/patch-v43/tools/sync_main.php             # починить
```

Локально 09.10.2026: dry-run — 63 КП / 136 итераций, прогон — столько же, повторный dry-run — 0.

## Часть 2c — расхождения с Битрикс24

Страница `/crm-monitor` («Расхождения с Битрикс24») и виджет стола `crm_mismatch` сверяли КП со сделками
своей логикой: сумма сделок КП против суммы одного КП. При общей сделке это давало ложное
«Сумма не сходится» у каждого КП и двойной счёт сделки в итогах. Теперь — сверка по кластеру.

### Что изменено

**`app/Modules/Pub/CrmMonitor/Services/CrmMismatchService.php`**

- Новый `clusters()`: одним запросом находит КП выборки, у которых хотя бы одна сделка привязана ещё к
  другому КП, и только для них зовёт `ProposalDealService::cluster()` (один обход на кластер, результат
  раздаётся всем его КП). КП кластера, не попавшие в выборку (фильтр по менеджеру, статусу, поиску),
  догружаются — сумма кластера от фильтра не зависит. Сделки кластера грузятся вместе со всеми.
- `check()` получил 4-й параметр `?array $cluster`. Если КП в общем кластере:
  - «Сумма не сходится» — сумма **уникальных** сделок кластера против суммы последних вариантов **всех**
    КП кластера, допуск прежний (`crm_amount_tolerance`); текст: «Сумма 3 сделок 2 689 920 против
    1 619 040 в КП OD454 + PG566 + OD586»;
  - валюта, «нет в выгрузке», стадия, «сделка не привязана», «нет расчёта» — по своим привязкам КП,
    как раньше (валюта сверяется с валютой этого КП);
  - в строке `proposal_total` / `deals_total` / `diff` — суммы кластера.
  `ProposalDealService::check()` целиком не переиспользован: он делает обход и запросы на каждое КП,
  допуск у него жёсткий 1, «сделки нет» и «сумма не указана» — ошибки по сделке, а у монитора другие
  виды расхождений и свой допуск. Переиспользован обход `cluster()` — состав кластера тот же, что в
  сводной карточке.
- Новые ключи строки:
  ```php
  'own_total' => сумма последнего варианта этого КП,
  'own_deals_total' => сумма своих сделок КП,
  'cluster' => [
      'shared' => bool,        // сделка общая с другими КП
      'key' => string,         // ключ кластера (у одиночного КП — его группа)
      'lead' => bool,          // ведущее КП кластера (у одиночного — всегда true)
      'lead_number' => ?string,// номер ведущего КП
      'others' => [{group, number, name, url, total}, ...], // другие КП кластера; url — сводная карточка
      'deal_ids' => [int, ...],
      'truncated' => bool,
  ]
  ```
- `money()` — суммы берутся по уникальным кластерам (`cluster.key`): каждая сделка и каждое расхождение
  входят один раз, сколько бы КП кластера ни попало в выборку. `count` — как раньше, число **КП** с
  расхождением суммы; новый `clusters` — число расхождений без повторов.

**Решение по итогам.** Ведущее КП кластера — с наименьшим id последней редакции. Расхождение кластера
показывается в колонке «Расхождение» только у него; у остальных КП кластера — «см. № OD454» (сумма в
подсказке). Счётчик «Сумма не сходится» считает КП (у каждого КП кластера есть расхождение — это правда),
а денежный итог — кластеры.

**`resources/views/themes/metronic/pub/crm_monitor/index.blade.php`**

- Колонка «Сделки Битрикс24»: под своими сделками — «сделка общая с КП AK727, …» (ссылки на сводные карточки).
- «В КП» — сумма кластера и ниже «в т. ч. это КП …»; «В Битрикс24» — сумма уникальных сделок и «N сделок вместе».
- «Расхождение» — у неведущих КП «см. № …».
- Плашка суммы (`?issue=amount`): если КП больше, чем расхождений, — «Общие сделки посчитаны один раз: расхождений N».

**`app/Modules/Pub/Desktop/Widgets/Funnel/CrmMismatchWidget.php`** — в строке списка новый ключ `shared`
(текст «Сделка общая с КП …», он же последней причиной в подсказке); `diff` у неведущих КП кластера — 0,
чтобы одна сумма не повторялась в нескольких строках. Итог «на …» — из `money()`, уже без задвоения.
В образце `shared` у одной строки.

**`resources/views/themes/metronic/pub/desktop/widgets/crm_mismatch.blade.php`** — значок-скрепка
`fa-link` у строки КП с общей сделкой (в таблице — в колонке «Что не так», в списке — `desk-hide-narrow`),
текст в подсказке.
