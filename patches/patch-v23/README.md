# Патч v23 — партнёры ↔ компании Битрикс24 (часть 1 итерации 3)

Ставится поверх v1–v22. В архиве только новые и изменённые файлы.

> **Это первая половина итерации 3.** Вкладки на карточке партнёра
> («Договоры» / «Сделки Битрикс», AJAX-маршрут `GET /partners/deals/{partner}`)
> в патч не входят — они делаются второй частью, после патча v22, потому что
> опираются на таблицу реестра сделок из него. Правая колонка карточки
> партнёра здесь не тронута.

## Что сделано

**1. Сопоставление партнёров с компаниями Битрикса**

Зеркало Битрикса (`avgbitrix`) перезаливается дампом целиком, поэтому колонок
туда не добавить — связь живёт в портале: новая таблица
`partner_crm_companies (id, partner_id, crm_company_id UNIQUE, created_at)`.
UNIQUE по `crm_company_id` и есть правило «одна компания Битрикса — не больше
чем у одного партнёра»; у партнёра компаний может быть несколько
(«Trafcoo (Taraf AI-Bader)» ↔ «Trafcoo», «Bifu» ↔ «Shanghai Bifu Testing
Technology Co., Lt»).

Модель `PartnerCrmCompany`, связь `Partner::crm_companies()` и хелпер
`Partner::crmCompanyIds()` — им дальше пользуются вкладка «Сделки Битрикс»
(вторая часть итерации), проекты (v24) и скоринг (v26):
`crm_deal.company_id IN crmCompanyIds()`.

Базы разные, поэтому Eloquent-связи сделаны по id + отдельная выборка, без
JOIN'а между соединениями. Там, где JOIN всё-таки нужен (разовый SQL ниже),
обязателен `COLLATE utf8mb4_unicode_ci`: у `avgmom` коллация
`utf8mb4_unicode_ci`, у `avgbitrix` — `utf8mb4_0900_ai_ci`, иначе MySQL
ругается «Illegal mix of collations».

**2. Разовое сопоставление по названию**

`database/sql/patch_v23_partner_match.sql` кладёт пары, у которых
`LOWER(TRIM(crm_company.title)) = LOWER(TRIM(partners.name))`. На боевых данных
(9 сентября) это **37 пар из 58 партнёров**. Запрос идемпотентный: `NOT EXISTS`
пропускает уже сопоставленные компании, повторный запуск ничего не добавляет.

Оставшийся **21 партнёр** сопоставляется руками в форме (список — в конце
README): у них названия в портале и в Битриксе просто разные («Techwizer» ↔
«TechWizer India», «МТ Интеграция» ↔ «МТ-Интеграция»), а у нескольких
(`test`, «Т1» и «T1» — дубли) пары в Битриксе и нет.

**3. Поле «Компании в Битрикс24» в форме партнёра**

В `create` и `edit` добавлен select2 multiple по всем компаниям зеркала
(383 строки, подпись — `title #id`). Компании, уже сопоставленные другому
партнёру, показываются с пометкой «занята: <партнёр>» и `disabled` — выбрать
их нельзя.

Клиентский `disabled` обходится подделкой запроса, поэтому
`PartnerCrmCompanyService::sync()` проверяет всё заново на сервере: компания
должна существовать в зеркале и не принадлежать другому партнёру, иначе
`ValidationException` и в ответе `{"result":"error","message":"..."}`.
Проверка идёт **до** сохранения остальных полей, чтобы не получилось
«наполовину сохранённой» формы. Тостер в форме теперь показывает текст
ошибки с сервера, а не общее «Не получилось сохранить данные».

**4. Карточка партнёра: блок «Битрикс24»**

В левой колонке под «Компаниями» — карточка «Битрикс24»: привязанные компании
(ссылка на карточку компании в Битриксе) и число их сделок **с 2025 года**
(константа `PartnerCrmCompanyService::DEALS_FROM`). Если привязок нет — вместо
списка подсказка «сопоставьте в редактировании» со ссылкой на форму. Компания,
которой уже нет в зеркале (дамп перезалили), остаётся в списке как
«компания #id» с пометкой — привязку видно и её можно снять.

Правая колонка («Договоры») не изменялась.

## Руками

1. Скопировать файлы патча поверх проекта.
2. `php artisan migrate` — применится
   `2026_09_09_120000_create_partner_crm_companies_table`.
3. Выполнить `database/sql/patch_v23_partner_match.sql`, **подключившись к базе
   портала** (той, что в `DB_DATABASE`):
   `mysql -u… <база_портала> < patch_v23_partner_match.sql`. Таблицы портала в
   запросе не квалифицированы именем базы намеренно, зеркало Битрикса всегда
   зовётся `avgbitrix` (`config/database.php`, соединение `bitrix`). Ожидаемый
   результат — 37 строк в `partner_crm_companies`. Повторный запуск безопасен.
4. `php artisan optimize:clear` (или хотя бы `view:clear`).
5. Сопоставить оставшийся 21 партнёр руками: `/partners/edit/{id}` → поле
   «Компании в Битрикс24». Пока партнёр не сопоставлен, его сделки Битрикса
   нигде не считаются (вкладка второй части, проекты v24, скоринг v26).

## Чек-лист проверки

- [ ] `php artisan migrate` создаёт `partner_crm_companies`.
- [ ] SQL сопоставления кладёт 37 пар; повторный запуск не дублирует
      (`SELECT COUNT(*) FROM partner_crm_companies` остаётся 37).
- [ ] `/partners/edit/{id}`: поле «Компании в Битрикс24» — select2 с поиском,
      выбранные компании показаны плашками.
- [ ] Компания, занятая другим партнёром, видна с пометкой «занята: …»
      и не выбирается кликом.
- [ ] Сохранение добавляет и снимает привязки; после снятия всех компаний
      строк у партнёра не остаётся.
- [ ] Подделанный запрос (`POST /api/partner/update/{id}` с чужой компанией)
      отвечает `{"result":"error"}` с понятным текстом, база не меняется.
- [ ] `/partners/detail/{id}`: блок «Битрикс24» показывает компании и число
      сделок с 2025 года — сверить с
      `SELECT COUNT(*) FROM avgbitrix.crm_deal WHERE company_id = … AND date_create >= '2025-01-01'`.
- [ ] У партнёра без сопоставления — подсказка со ссылкой на редактирование.
- [ ] Правая колонка карточки («Договоры») выглядит как раньше.
