# Патч v34 — рабочий стол: задачи в блокноте, календарь, стартовые столы, аудит 80 виджетов

Партия правок рабочего стола 23.09.2026: запросы владельца по отдельным виджетам, пять системных
стартовых столов и аудит всех 80 виджетов — вёрстка по сетке 2…16 × 2…32 и неточности в данных
(сверка с отчётами-источниками). Итоги аудита по группам — `patches/patch-v30/grid/{группа}.md`
(раздел «Аудит 23.09.2026» у каждого виджета).

## Запросы владельца

- **Блокнот → задачи.** Флажок «сделано» в начале строки (`api.user-notes.done`, колонка
  `user_notes.done_at`), выполненные — зачёркнуты и внизу списка. Настройка «Выполненные задачи»:
  показывать сутки, потом скрывать (по умолчанию) / внизу списка / сразу скрывать. Звезда — только у
  избранных, после названия. Описание стоит сразу за названием, дата прижата вправо. В сайдбаре правки —
  флажок «Задача выполнена». **Правка заметки больше не пересоздаёт её** (раньше удаляла и создавала
  заново: менялись id и дата создания, терялось напоминание).
- **Календарь как в Windows 11.** Стрелки ↑↓ по месяцам, клик по заголовку — плитки месяцев, ещё
  клик — плитки лет; «сегодня». Дни с событиями — кружок цвета события, сегодня — сплошной синий,
  выбранный — кольцо. Клик по дню — панель дня: события (сайдбар), «+ Новое событие» с датой дня
  (`calendar.sidebar_add?date=`). В широком блоке панель справа от месяца, в узком — вместо него.
  После сохранения события виджет обновляется без перезагрузки страницы.
- **Сайдбар события (Metronic).** Новая вёрстка `themes/metronic/pub/calendar/sidebars/` (общая форма
  `_form` для создания и правки): переключатель «Весь день · Период · По времени (· На будущее)»,
  цвета кружками. Исправлено: дубль id «Диапазона дат», в правке не подставлялся период дат
  (`$event->type` вместо `mode`), у «Периода» при создании было `all_day = 0` («00:00» в календаре).
  Старая тема не тронута.
- **Курсы валют:** третья валюта в 8×3 (строки плотнее при высоте < 160 px).
- **Значки.** Подключён Font Awesome Pro **6.0.0**; значков из 6.1+ нет. Заменены 7 несуществующих:
  `money-bill-transfer` → `coins`, `building-circle-arrow-right` / `building-lock` → `building`,
  `plug-circle-xmark` → `link-slash`, `ranking-star` → `trophy`, `shield-halved` → `shield`,
  `users-line` → `users`.
- **Блок высотой 1** — без заголовка (`Widget::html`), тело почти без вертикальных отступов.
- **«Действие»** — одинаковый отступ кнопки со всех сторон.

## Ядро стола (общие файлы)

- **Состояние просмотра блока** (`Widget::viewState()`, третий аргумент `data()`/`sample()`, `$view`
  во вьюхе, ключ кэша): клик по `[data-desk-view='{"month":"2026-10"}']` перерисовывает блок, в
  настройках не хранится. Стенд: `widget_grid.php … --view='{…}'`.
- **Действие без перехода** `[data-desk-post="url"]` — POST и перерисовка всех блоков виджета.
- **Событие** `$(document).trigger('desk:refresh', ['notebook'])` — сайдбары обновляют виджеты.
- `osmo-desktop-fit.js`: `data-fit-extra="N"` на подписи «ещё {n}» — строки, отсечённые сервером
  лимитом (scoring_top, partners_new, specs_reconcile).
- `osmo-desktop.css`: утилита `.min-w-0` (в бандле Metronic её нет, а 10 вьюх на неё рассчитывали);
  несколько `.desk-cut` в строке таблицы делят ширину поровну (раньше первая забирала всё); левый
  отступ таблицы, когда первая колонка спрятана по ширине.
- `osmo-desktop-charts.js`: цвета `#rrggbb` проходят как есть (кольцо грейдов).
- `MetricRegistry`: подпись квартала «3 кв. 26» вместо «Q3 26».

## Стартовые столы

Команда `php artisan desktop:presets` (`app/Console/Commands/DesktopPresetsCommand.php`,
`--dry-run`, `--user=ID`): пять системных пресетов из проекта стола — **Руководитель** (по умолчанию
для новых пользователей), **Менеджер продаж**, **Финансы**, **Ключи и продления**, **Аналитик**.
Идемпотентна: пресет ищется по имени, `version` растёт только при изменении состава. Проверяет
виджеты, настройки, пересечения и размеры до записи. Замены против проекта: в «Финансах» вместо
«Журнала изменений» (виден только с правом журнала) — график «Оплаты по месяцам»; в «Ключах» вместо
двух «Карточек ключа» (нужен конкретный ключ) — «Число: продления за 90 дней» и кнопка «Реестр
лицензий»; у «Сравнения» показатель «КП выиграно, сумма» (у воронки нет ряда).

## Аудит виджетов — главное

Вёрстка: у всех 80 виджетов нет кодов X/C/H/F/G; суммы и числа нигде не уходят в многоточие;
переписаны под любой размер `compare`, `period`, `team` (без прокрутки), `embed` (превью),
`payments_by_partner` (обрезался и пустовал), `heading`. Неточности, которые врали цифрами:

- **china** — сумма КП договора повторялась в каждой строке его ключа: 28,9 млн ₽ вместо 16,6.
- **scenarios_top** — считались все редакции КП: 1292 упоминания вместо 587.
- **deals_quarter** — в план попадали отменённые сделки (118 млн из 1 026 млн в 2026).
- **companies_geo** — в сумму спецификаций входили отменённые (104,3 млн вместо 98,4).
- **projects** — сумма по первым 8 проектам, счётчик по всем.
- **proposals_mine / proposals_recent** — «старше 14 дн.» и «за неделю» по показанным строкам
  (10 вместо 17 и 81); второстепенные КП — ветками под главным, как на `/proposals`.
- **keys** — ссылки на реестр открывали горизонт 90 дней (14 строк вместо 55); партнёр ключа без
  спецификации не находился (60 ключей из 99).
- **specs_reconcile** — 17 строк «−0 ₽» (расходилась сумма КП, а показывалось расхождение платежей).
- **manager_quarter / country_quarter** — неверное «Не выбрано: 13 сделок» (квартал у всех есть,
  они вне показанных столбцов).
- **deals_top** — ссылка открывала реестр с отбором «без КП»; **funnel_stages** — в настройке была
  стадия, которую воронка не считает (пустой виджет).
- **external_proposals** — «за 7 дней» считало 8; **proposal_conversion** — будущие месяцы как 0 %;
  **progress** — кольцо «100 %» при перевыполнении; **rates/currency** — сум «0,01 ₽»;
  **journal** — ссылка на КП по id (404); **changes** — ссылка на ленту удалённого объекта (404);
  **button** — «Спрашивать подтверждение» не останавливал попап и сайдбар;
  **countdown** — дата «2026-12-31» роняла виджет; **clock** — время «прыгало» в 12-часовом формате;
  **reminders / notifications** — сводки по видимым строкам, HTML-сущности буквами.
- Опечатка «лиценцзий» в проблемах сделок (`CrmDealIssues`, видна и на воронке).

## Решения владельца 23.09.2026 (по итогам аудита)

1. **Воркер очереди на проде настроен.** Раньше воркера не было: напоминания с 2024 года лежали в
   `jobs`, уведомления и письма не уходили. Теперь supervisor, `/etc/supervisor/conf.d/osmo.conf`
   (программа `osmo_queue`, пользователь `www-root`, `queue:work database --queue=database,default
   --tries=3 --max-time=3600`, лог `storage/logs/queue-worker.log`). Три тестовых напоминания Анны
   2024 года («test») сняты из очереди по решению владельца, `reminder_times` 3–5 помечены
   отработанными. Проверено заданием канала «Лог» — воркер его взял; попутно найдена и исправлена
   ошибка в `LogNotification` (обращалась к несуществующим `$this->title`/`$this->message`).
   Конфиг — копия в `patches/patch-v34/server/osmo-queue.conf`.
2. **КП AM516 «НГМК» закрыто** (прод и локально): «Проиграно», причина «Отменено», комментарий
   «Закрыто по решению владельца 23.09.2026: КП не нужно» — через `ProposalStatusService` (журнал
   изменений есть). «КП в работе, сумма» больше не раздута на 12,9 млрд ₽.
3. **Дата выигрыша КП** — если КП привязано к спецификации (`contract_specification_proposals`),
   это дата первой фактической оплаты по её платежам; иначе — дата смены статуса, как было.
   Показатели «Выиграно за период», конверсия, сравнения и графики больше не сваливают все победы в
   III квартал 2026: по кварталам 2024-Q3…2026-Q3 теперь 1/6/1/1/3/7/1/9 (было 29 в 2026-Q3; в нём
   остались 5 КП со спецификацией без оплат и 4 без спецификации). «Выиграно за период, сумма» за
   текущий квартал — 13,0 млн ₽ вместо 56,8. `MetricRegistry::wonDates()` / `decidedDates()`.
4. **Сравнение «к прошлому периоду» — по то же число** для фактических показателей (оплаты факт,
   выигрыши, отправленные КП, конверсия, новые партнёры): 01.07–23.09 против 01.04–23.06. Прогнозные
   (продления ключей, план оплат) сравниваются целиком, как раньше. В последний день периода прошлый
   берётся целиком. У «Сравнения периодов» пара «идущий / такой же прошлый» подписана «по 23.09 /
   по 23.06». `DesktopContext::previousRange($key, $now, $to_date)`, `previousPeriod()`.
5. **`Execution (PRE-PAYMENT)` — завершённая сделка** (оплата уже прошла, на неё не рассчитывают):
   в воронке её и так не было; «Крупные сделки» в режиме «Активные стадии» её больше не берут,
   «Сделки по кварталам» относят к завершённым (`DealsQuarterWidget::CLOSED`).
6. **Суммы ключей**: каждая спецификация считается один раз — если по ней выдано несколько ключей
   (корабли РРПК, лидары ЦОДД), её сумма делится между ними поровну; на странице «Реестр лицензий»
   под суммой такого ключа — «1/N спецификации» с подсказкой (`LicenseRegistryService::decorate()`,
   так же уже считал `LicenseRenewalService`). Итог реестра 46,5 млн ₽ вместо 48,0.
   **Открыто:** случай МТИ (договор L-PG-303.25, «Метрополитен»: «С.1_Метро (Платформа)» с ключом
   126 и «С.2_Метро (Нейронки)» без ключа — проект и ключ один, спецификаций две). Автоматически
   связать их нельзя: у РРПК в одном договоре каждая спецификация — свой корабль со своим ключом.
   Нужна явная привязка ключа к нескольким спецификациям (отдельная задача).
7. **Саудовский риял — код `SAR`** (было `SRD` «Саудовский реал», хотя `SRD` — суринамский доллар):
   миграция `2026_09_23_160000_rename_currency_srd_to_sar` меняет код в справочнике, курсах (146),
   КП (2), договорах, спецификациях, доплатах и контексте столов; `currency:fetch-rates` берёт `SAR`
   у ЦБ напрямую, без псевдонима (ЦБ: «Саудовский риял» 22,4175 ₽ на 23.09.2026).

## Выкатка

1. Копия базы прода в `/root/backup` (правило: перед любым изменением БД).
2. `git pull`, `composer dump-autoload`.
3. `php artisan migrate` — две миграции (`user_notes.done_at`, код валюты SAR).
4. `php artisan desktop:presets --dry-run`, затем `php artisan desktop:presets` — пять пресетов.
5. `php artisan optimize:clear` и `php artisan cache:clear` — у виджетов поменялся формат данных.
6. `php artisan queue:restart` — воркер `osmo_queue` подхватит новый код (supervisor поднимет его сам).
7. У пользователей CSS/JS стола может закэшироваться (JS подключается без версии) — Ctrl+F5.

## Открыто

0. **Конверсия КП перекошена датами проигрышей.** Выигрыши теперь датируются первой оплатой, а у
   всех 71 проигранных КП `status_changed_at` проставлен пачкой в III квартале 2026 (массовая смена
   статусов в v27). Конверсия за текущий квартал — 11,3 % (9 из 80). Варианты: датировать и
   проигрыши иначе (например, датой отправки для проставленных пачкой) или считать конверсию по
   когорте «отправлены в периоде → доля выигранных среди решённых».
1. **На проде `APP_ENV=development`.** В этом режиме `EmailNotification` отправляет **все письма
   напоминаний на avg.den@yandex.ru** вместо адреса пользователя. С работающим воркером письма
   пойдут туда. Если письма должны уходить пользователям — `APP_ENV=production` в `.env` прода
   (решение владельца; проверить, что больше ничего не завязано на `development`).
2. **МТИ: ключ на несколько спецификаций** — см. п. 6 выше.
3. **Suspended** в «Сделках по кварталам» — больше половины суммы в отборе «Все, кроме отменённых»;
