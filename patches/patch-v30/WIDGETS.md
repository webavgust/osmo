## Как устроен виджет (соглашение с 14.09.2026)

Виджет — класс `app/Modules/Pub/Desktop/Widgets/{Категория}/{Имя}Widget.php` (наследник
`App\Modules\Pub\Desktop\Widgets\Widget`) плюс вьюха тела
`resources/views/themes/metronic/pub/desktop/widgets/{id}.blade.php`. Реестр
(`WidgetRegistry`) находит виджет сам — общие файлы править не нужно.

**Размер блока произвольный.** Пользователь снимает замок размеров и тянет угол как хочет,
поэтому виджет обязан выглядеть прилично в любом прямоугольнике, а не только в объявленных
`sizes()`. Правила:

1. Вьюха **никогда** не сравнивает `$w`, `$h` или `$size` с числами. Ступени:
   - `$dw` — ширина: `xs` (1–2 колонки), `sm` (3–5), `md` (6–11), `lg` (12–23), `xl` (24+);
   - `$dh` — высота: `xs` (1 ячейка), `sm` (2), `md` (3–5), `lg` (6–9), `xl` (10+);
   - `$rows` — сколько строк списка или таблицы влезет по высоте (уже с учётом заголовка).
   Ступени решают, **что** показывать (таблица или список, есть ли подпись), контейнерные
   запросы в CSS — **как** это выглядит.
2. Списки и таблицы режутся `array_slice($data['rows'], 0, $rows)` и лежат в `.desk-scroll`
   (прокрутка) или `.desk-clip` (обрезка с растворением).
3. Второстепенное прячется классами, а не PHP: `.desk-only-w-md` (шире 230 px),
   `.desk-only-w-lg` (420), `.desk-only-w-xl` (620), `.desk-only-h-md` (выше 110 px),
   `.desk-only-h-lg` (230), `.desk-hide-narrow` (уже 170 px), `.desk-hide-short` (ниже 96 px).
   На `<th>`/`<td>` они прячут колонку целиком.
4. Крупное число — `.desk-value` (кегль считается от площади блока), помельче —
   `.desk-value-sm`, покрупнее — `.desk-value-lg`. Никаких размеров шрифта в стилях виджета.
5. Длинный текст — `.desk-grow` в строке флекса, `.desk-nowrap` в колонке, `.desk-cut` в
   ячейке таблицы; всегда с `title`.
6. Готовые классы тел: `.desk-center`, `.desk-stack` + `.desk-stack-grow`, `.desk-list`,
   `.desk-table` (+ `.num`, `.desk-cut`, `.desk-total` на итоговой строке), `.desk-bar > i`
   (цвет — утилитой `bg-*`, ширину растянуть `.desk-bar-fill`), `.desk-split` (полоска из
   разноцветных долей), `.desk-grid-7` (семь равных колонок), `.desk-tiles`, `.desk-label`,
   `.desk-muted`, `.desk-delta.up|down|flat`, `.desk-empty`, `.desk-bleed` (тело во всю
   площадь), `.desk-scroll` / `.desk-clip`.
   Остальное — утилиты Metronic (`badge`, `symbol`, `bullet`, `fs-8`, `text-truncate`).
   `.desk-center` и `.desk-stack` сами обрезают содержимое, которое не влезло, — блок
   виджета никогда не прокручивается целиком. Шапка `.desk-table` внутри `.desk-scroll`
   липкая сама по себе — своих `position: sticky` не нужно.
7. Деньги — `$widget::money($amount, $data['symbol'])`, крупные числа — `$widget::compact()`,
   суммы полностью в `title` (`money(..., false)`).
8. Число строк зависит от ширины экрана (сторона ячейки 40–64 px), поэтому списки и таблицы
   режутся не точно, а с запасом: `array_slice($rows, 0, $rows_max)` в контейнере `.desk-fit` —
   `osmo-desktop-fit.js` спрячет строки, не влезшие целиком. Атрибуты контейнера:
   `data-fit-items="tbody > tr"` (свой выбор строк), `data-fit-axis="x"` (подгон по ширине —
   чипы, колонки), `data-fit-min` (сколько строк оставить всегда, по умолчанию 1); подпись
   `[data-fit-more="ещё {n}"]` внутри контейнера или сразу за ним.
9. Стили отдельного виджета — только в `public/metronic/css/osmo-desktop-widgets/*.css`,
   селектор начинается с `.desk-widget[data-widget="{id}"]`, кегль — контейнерными единицами.

### Прогон по сетке — после любой правки виджета

Виджет, у которого поменяли вьюху, класс, `sample()` или стили, прогоняют по всей сетке —
ширина 2…16 и высота 2…32 с шагом 2, 128 размеров:

```
php patches/patch-v30/tools/widget_grid.php {id}                       — матрица кодов
php patches/patch-v30/tools/widget_grid.php {id} --detail=4x2,8x8      — что видно в размере
php patches/patch-v30/tools/widget_grid.php {id} --live --sizes=4x2,8x8,16x16
php patches/patch-v30/tools/widget_grid.php {id} --settings='{"show_title":false}'
```

Стенд рисует виджет сервером во всех размерах на одной странице (как на столе при окне 1920:
ячейка 47,25 px, отступ 8 px), открывает её в безголовом Edge и меряет скриптом в странице
(`tools/widget_grid.js`). Страница и отчёт — `storage/app/desk-grid/{id}.html|json`.

Коды в матрице («·» — замечаний нет):

| Код | Что значит | Допустимо |
|---|---|---|
| X | исключение или плашка «Не удалось показать виджет» | нет |
| C | элемент обрезан краем блока посередине | нет |
| H | элемент целиком спрятан обрезкой (нарисован, но не виден) | нет — прятать классами или `.desk-fit` |
| F | шрифт мельче 10 px | нет |
| G | график ниже 40 px | нет — прятать график, оставлять число |
| T | многоточие | только на второстепенном тексте с `title`; числа и суммы — никогда |
| e | содержимое занимает меньше четверти тела | на крошечных блоках (2×2) — да; крупные блоки не пустуют |
| s | часть содержимого в прокрутке | только в реестрах, где строк заведомо больше |
| f | подгон `.desk-fit` спрятал строки | да |

Образец `sample()` должен давать столько строк, чтобы заполнить высокий блок (до ~40), иначе
высокие размеры пустуют из-за образца, а не из-за вьюхи. Результат прогона по виджету —
таблица «размер → что показывается» в `patches/patch-v30/grid/`.

**Контракт класса:** `id`, `name`, `category`, `sizes`, `defaultSize`, `description`, `icon`,
`order`, `fields` (схема настроек), `usesCurrency`, `usesPeriod`, `available` (право),
`ttl` (кэш данных), `sourceUrl` (страница-источник), `data()` (только массивы и скаляры),
`sample()` (образцовые данные для превью библиотеки), `previewSettings()`.

**Данные** берутся сервисами модулей под текущим пользователем — стол не даёт доступа
к тому, чего нет на страницах. Валюта и период — из `DesktopContext`
(`$ctx->currencyFor($settings)`, `$ctx->range($settings)`), пересчёт сумм —
`CurrencyService::convertAmount()`.


## Общие (`common`, 16)

Универсальные блоки: показатели из реестра, контекст стола, ссылки, баннеры

### ✔ Число (показатель) — `kpi`

- Размеры: 2×2, 4×2*, 4×4, 8×4
- Источник: Реестр показателей `MetricRegistry` → сервисы модулей (`DashboardDataService`, `ProposalStatusService`, `PaymentCalendarService`, `LicenseRenewalService`…)
- Логика: Одно число крупно. Меняется валюта или период на столе — пересчитывается. Дельта — отношение к предыдущему такому же отрезку. На 2×2 только число, на 4×4 и 8×4 добавляется спарклайн за 12 периодов.
- Настройки:
  - Показатель из реестра (воронка → сумма сделок / лицензий / услуг / разработки / платформы; КП → в работе, выиграно, конверсия; оплаты → факт, план; ключи → истекающие; партнёры → количество…)
  - Период: со стола / свой
  - Валюта: со стола / рубли / принудительно
  - Размер шрифта и заливка
  - Сравнение с прошлым таким же периодом
  - Ссылка по клику

### ✔ Выбор валюты — `currency`

- Размеры: 4×2*, 8×2
- Источник: `currencies`, `currency_rates` (курсы ЦБ, `CurrencyService`)

- Настройки:
  - Список валют: все активные / выбранные
  - Валюта по умолчанию для стола

### ✔ Период — `period`

  - Период по умолчанию

- Настройки:
  - Уровень расхождения: любые / только жёсткие
  - Партнёр

### ✔ Договоры без подписи — `contracts_unsigned`

## Ключи и лицензии (`keys`, 5)

Истекающие ключи, продления, реестр лицензий

### ✔ Истекающие ключи — `keys_expiring`

- Размеры: 4×2*, 8×2, 4×4
- Источник: `license_keys.active_to` (`LicenseRenewalService::expiring / renewalAmount`)
- Логика: Число ключей, истекающих в горизонте, и сумма продления. Истёкшие в «хвосте» (`license_expired_tail_days`) — отдельно красным. Клик — реестр лицензий с этим горизонтом.
- Настройки:
  - N дней: 30 / 60 / 90 или горизонты из константы `license_horizons`
  - Только активные
  - Компания / партнёр

### ✔ Реестр лицензий — `license_registry`

- Размеры: 16×8*, 32×8, 32×12
- Источник: `LicenseRegistryService::rows / bucket / state`
- Логика: Компактный реестр: партнёр → компания, договор и спецификация, начало, окончание, осталось, сумма; цвет состояния как на странице. «Все» — переход в реестр.
- Настройки:
  - Горизонт
  - Скрыть истёкшие
  - Партнёр
  - Колонки

### ✔ Продление лицензий — `renewals`

- Размеры: 8×4*, 8×8
- Источник: `LicenseRenewalService::summary` (горизонты 30 / 60 / 90, истёкшие)
- Логика: Суммы продлений по горизонтам и число ключей; доля «уже продлено» (новый ключ той же компании) — кольцом на 8×8. Клик — реестр.
- Настройки:
  - Валюта
  - Партнёр

### ✔ Ключи по компаниям — `keys_by_company`

- Размеры: 8×4*, 8×8
- Источник: `license_keys`, `companies`
- Логика: Где сосредоточены активные лицензии. Клик — карточка компании.
- Настройки:
  - Разрез: компания / партнёр / страна
  - Только активные

### ✔ Карточка ключа — `key_card`

- Размеры: 4×2*, 8×2
- Источник: `license_keys` + спецификация
- Логика: Один ключ на контроле: компания, срок, состояние, спецификация. Клик — отчёт «Ключи».
- Настройки:
  - Ключ (поиск по компании)

## Администрирование (`admin`, 4)

Только для админа: пользователи, входы, константы, состояние портала

### ✔ Пользователи: активность — `users_online`

- Размеры: 8×4*
- Источник: `users.last_hit_at`, `user_auth_attempts`
- Логика: Кто в сети, последние входы, неудачные попытки за сутки. Клик — карточка пользователя в админ-панели. Только для админа.
- Настройки:
  - Показывать неудачные попытки за сутки

### ✔ Неудачные входы — `auth_failed`

- Размеры: 4×2, 8×4*
- Источник: `user_auth_attempts.success = 0`
- Логика: Попытки входа с логином и IP. Всплеск выше порога — красный счётчик. Только для админа.
- Настройки:
  - Период: 24 часа / 7 дней
  - Порог всплеска

### ✔ Константы на контроле — `consts_watch`

- Размеры: 8×4*
- Источник: `consts` (patch v28)
- Логика: Текущие значения ключевых констант (веса скоринга, пороги, горизонты) с датой изменения. Клик — админ-панель констант. Только для админа.
- Настройки:
  - Выбранные константы

### ✔ Состояние портала — `system_health`

- Размеры: 8×4*
- Источник: `jobs` / `failed_jobs`, даты синхронизаций, `currency_rates`, размер `laravel.log`
- Логика: Светофор по подсистемам: красный — есть failed jobs или курсы старше 2 дней, жёлтый — синхронизация старше суток. Только для админа.
- Настройки:
  - Подсистемы: очередь, синхронизация Битрикс24, OSMOVIEW CP, курсы валют, журнал ошибок
