## Часть 1. Платёжный календарь

**1. Вместо месяца выводились «0000».**
`translatedFormat('LLLL')` — это не месяц: в формате PHP `L` означает
«високосный год», отсюда и нули. Название месяца даёт `isoFormat('MMMM')`.
Исправлено в `PaymentCalendarService::months()`.

**2. Цифры кликабельные, видно из чего сложились.**
Каждая сумма — ссылка, которая сохраняет текущий отбор и добавляет своё
условие, после чего таблица платежей внизу показывает ровно те платежи,
из которых эта сумма и получилась. Над таблицей появилась строка «Отбор»
с условиями: каждое можно снять по отдельности.

Кликаются: четыре верхних показателя, корзины просрочки, название месяца,
план, факт и просрочка в каждой строке месяца.

**3. Огромная сумма в блоке «Просрочено».**
Три причины, все закрыты:

- считались платежи **отменённых спецификаций** (см. п. 6);
- считались платежи по **архивным договорам** (`contracts.old`) — теперь
  они исключены, включить обратно можно галочкой «с архивными»;
- по числу было непонятно, что там древние долги: под суммой появились
  корзины **до 30 дней / 31–90 / 91–365 / больше года** с суммой и
  количеством, каждая кликается. Подпись «за все годы» — показатели
  умышленно не ограничены выбранным годом, просрочка прошлых лет не
  перестаёт быть просрочкой.

**4. Верхние блоки кликабельные** — просрочено, ждём в 14 дней, поступило
в этом месяце (ведёт на текущий месяц), без даты. Там же кликабельная
плашка «отменённые спецификации», если такие есть.

**5. В таблице платежей теперь видно, откуда сумма.**
Колонки: состояние, **КП** (номер и название), **компания**, **договор и
спецификация**, план, факт, сумма, цепочка. В сумме мелким шрифтом —
сумма спецификации, чтобы сравнить платёж с ней.

**6. Статус «Отменена» больше не даёт просроченный платёж.**
Появилось состояние **«Спец. отменена»** (`ContractSpecificationStatus::CANCELED`):
такой платёж не попадает ни в просрочку, ни в план, ни в разбивку по месяцам.
Уже оплаченный платёж остаётся оплаченным — деньги-то пришли.

**7. Ссылки.** КП → карточка КП, компания → `company.detail`,
договор → попап `contract.box_edit`, спецификация → попап
`contract_spec.box_edit`, цепочка → сквозная карточка.
Заодно ушёл `Proposal::find()` в цикле — КП подтягивается тем же запросом.

Фильтры дополнены компанией; поиск ищет ещё по номеру и названию КП.

## Часть 2. Цепочка КП

**1. У одного КП может быть несколько сделок Битрикса.**
Связь переведена в «много ко многим»: новая таблица `proposal_crm_deals`
(`proposal_group` + `crm_deal_id`, одна из привязок помечена главной).
Миграция создаёт таблицу и переносит в неё то, что уже привязано.

`proposals.crm_deal_id` остаётся — там теперь **главная сделка**. Так
продолжает работать всё, что читает колонку напрямую (колонка в списке КП,
выгрузки), а фильтры списка переведены на новую таблицу.

Попап привязки переписан: сверху список привязанных сделок с кнопками
«сделать главной» и «отвязать», ниже прежний поиск. Привязка нескольких
сделок идёт без перезагрузки страницы; страница обновляется при закрытии
попапа. Обратное ограничение сохранено: одна сделка принадлежит одному КП,
иначе сверка с CRM начнёт двоить суммы.

В сквозной карточке шаг «Сделки Битрикс24» показывает количество и главную,
а внизу появился раздел со всеми сделками: стадия, ответственный, сумма.

**2. Договор не зелёный, если подписаны не все.**
Шаг «Договоры» зелёный только когда подписаны **все** действующие договоры;
иначе жёлтый с перечислением неподписанных. Архивные договоры в оценке
не участвуют. Значение шага теперь «Подписано 2 из 3».

**3. То же у спецификаций.** Зелёный — только когда подписаны все
действующие. Отменённые спецификации из оценки выпадают, но видны в
подсказке («отменено: 2») и в таблице — зачёркнутой суммой и статусом.
Суммы «Деньги по сделке» считаются без отменённых, отдельной строкой
показано, на сколько отменено.

## Часть 3. Патч C

### История изменения цен

Страница `/proposal-tools/price-history/{group}`, открывается кнопками
«История цен» и «Как менялась цена» из сквозной карточки. Новых таблиц не
требует — считает по существующим редакциям КП.

Сверху: первая редакция, последняя, изменение в деньгах и процентах.
Дальше таблица редакций: платформа, нейросервисы, ПО, работы, НДС, итого и
**Δ к предыдущей редакции**.

Ниже — сравнение двух редакций по позициям (по умолчанию предпоследняя
против последней): было / стало / Δ и метка **новая позиция**, **убрана**,
**цена изменилась**, **без изменений**. Позиции сопоставляются по названию
внутри блока: id у каждой редакции свои, а название — то, что видит заказчик.

### Клонирование КП

Попап «Клонировать» из сквозной карточки. Копия — это **новое КП** (новая
группа, первая редакция), а не новая редакция.

Переносим: платформу, сценарии с привязкой нейросервисов, ПО, работы,
вычислительные ресурсы, дополнительные платежи, все варианты и скидки.
Не переносим: статус, привязки к сделкам Битрикса, ссылку на родительскую
редакцию, договоры, спецификации, платежи.

В попапе можно сразу сменить название, номер, дату, компанию, партнёра и
менеджера. Логика копирования повторяет `ProposalRepository::convert()`,
поэтому ведёт себя предсказуемо на тех же данных.

## Что нужно сделать руками

**1. Миграция и SQL**

```bash
php artisan migrate                   # proposal_crm_deals
mysql ... < database/sql/patch_c_access.sql   # права (по желанию)
```

**2. Кнопки в карточке КП** (`resources/views/themes/metronic/pub/proposal/detail.blade.php`,
в `card-toolbar` рядом с остальными кнопками):

```blade
<a href="{{ route('proposal_tools.price_history', $proposal) }}" class="btn btn-sm btn-light">
    <i class="fa-light fa-chart-line fs-5 me-2"></i>История цен
</a>
<a href="javascript:box({href: '{{ route('proposal_tools.box_clone', [$proposal, $proposal->iteration]) }}'})"
   class="btn btn-sm btn-light">
    <i class="fa-light fa-clone fs-5 me-2"></i>Клонировать
</a>
```

**3. Необязательно — связь в модели** `app/Modules/Pub/Proposal/Models/Proposal.php`,
если удобно обращаться к привязкам напрямую:

```php
public function crm_deals()
{
    return $this->hasMany(\App\Modules\Pub\Proposal\Models\ProposalCrmDeal::class, 'proposal_group', 'group')
        ->orderByDesc('is_main');
}
```

Сервис `ProposalDealService::links($proposal)` работает и без неё.

## Проверка после установки

- [ ] в календаре месяцы называются месяцами, а не «0000»
- [ ] клик по «Просрочено» открывает те же платежи внизу, строка «Отбор» это подтверждает
- [ ] сумма просрочки разложена по корзинам, суммы корзин складываются в общую
- [ ] платёж отменённой спецификации не числится просроченным
- [ ] в таблице платежей видно КП, компанию, договор и спецификацию, ссылки открываются
- [ ] галочка «с архивными» меняет суммы показателей
- [ ] к одному КП привязываются две и более сделки, главная переключается
- [ ] в списке КП бейдж показывает «Сделка #… +1», фильтр по наличию сделки работает
- [ ] в цепочке договор жёлтый, пока подписан не каждый; то же у спецификаций
- [ ] история цен открывается, Δ между редакциями считается
- [ ] сравнение редакций показывает новые, убранные и подорожавшие позиции
- [ ] клонирование создаёт новое КП с тем же расчётом и пустым статусом
