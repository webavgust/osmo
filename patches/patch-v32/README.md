# Патч v32 — журнал изменений у проектов по сделкам

Проекты по сделкам Битрикс24 (patch v24) подключены к журналу изменений сущностей (patch v29):
любая правка проекта, его сделок и спецификаций попадает в ленту `/timeline/deal_project/{id}`.

## Что сделано

**Что пишется в журнал**
- Проект: партнёр, компания, дата начала, пилот, срок пилота, комментарий, отправка в архив
  («В архиве с», «Отправил в архив») и возврат из архива.
- Сделки проекта: прикрепление и открепление («Сделка #319 «…»» — добавлено / удалено).
- Спецификации проекта: отнесение и снятие, смена признака «Из КП сделки».
- Автор события и время — как у КП, партнёров и компаний.

**Где смотреть.** В карточке проекта (попап из реестра сделок и вкладок партнёра) появилась кнопка
«Журнал изменений» — для тех, у кого есть право смотреть журнал. В крошках ленты — «Реестр сделок
Битрикс24 → Проект от … · Партнёр → Журнал изменений»; «К объекту» ведёт в реестр на вкладку
проектов (или архива) с поиском по сделке проекта.

**Без «состояния на дату».** Своей страницы у проекта нет — карточка проекта попап, поэтому ссылок
«Открыть состояние на этот момент» в ленте проекта нет (у КП, партнёров и компаний они остаются).
Для этого в контракт журнала добавлен `logStateView()` (по умолчанию «да»).

**Массовые правки.** Открепление сделки и пересборка спецификаций проекта идут массовыми
`delete`/`update`, которые не вызывают событий модели, — они обёрнуты в `EntityLogService::around()`,
иначе журнал их не увидел бы.

Проверено на живом проекте в транзакции с откатом: правка (пилот, срок, комментарий) — 3 строки,
архив — 2 строки («В архиве с», «Отправил в архив»), открепление сделки — 1 строка «удалено».

## Файлы

**Изменённые**
- `config/entity_log.php` — корень `deal_project`
- `app/Modules/Pub/DealProject/Models/DealProject.php` — `HasLogger`, поля, дети, подпись, ссылка
- `app/Modules/Pub/DealProject/Models/DealProjectDeal.php`,
  `app/Modules/Pub/DealProject/Models/DealProjectSpecification.php` — `HasLogger`, части проекта
- `app/Modules/Pub/DealProject/Services/DealProjectService.php` — массовые правки через `around()`
- `app/Models/Traits/HasLogger.php` — `logStateView()`
- `app/Modules/Pub/EntityLog/Controllers/EntityLogController.php` — раздел в крошках, ссылки
  состояния только у корней со страницей состояния
- `resources/views/themes/metronic/pub/deal_project/boxes/info.blade.php` — кнопка журнала

## Руками

1. `git pull`
2. `php artisan optimize:clear`
3. `php artisan entity-log:baseline` — снимет первые слепки проектов (КП, партнёры и компании,
   у которых слепки уже есть, пропускаются). Без этого первый слепок снимется сам при первой правке.

Миграций и SQL-файлов в патче нет.

## Чек-лист проверки

- [ ] Карточка проекта: кнопка «Журнал изменений» (у админа), ведёт в ленту проекта
- [ ] Правка проекта (пилот, срок, комментарий) — событие со строками по полям
- [ ] Архив и возврат — строки «В архиве с», «Отправил в архив»
- [ ] Прикрепить и открепить сделку — строки «добавлено» / «удалено»
- [ ] Отметить спецификацию в проекте — строка «добавлено»
- [ ] В ленте проекта нет ссылок «состояние на момент»; у КП они на месте
