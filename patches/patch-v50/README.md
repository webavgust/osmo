# patch v50 — отчёт «Движение сделок за год» (запрос владельца 16.11.2026)

Ставится поверх v49. Новая страница **`/bitrix/movement`** (маршрут `bitrix.movement`) — отдельный пункт меню
«Движение сделок»: сколько новых запросов пришло за год и где они сейчас / на конец года, сколько сделок за год
отвалилось и закончилось, и диаграмма Ганта по сделкам года. Решения владельца — `patches/PLAN.md`, «Итерация 27».
Старый адрес `/bitrix/dashboard/movement` отвечает 301 на новый с тем же query.

## Что поменялось

1. **Сервис `DealMovementService`** (модуль `Bitrix/Dashboard`). Источник — зеркало Битрикс24: `crm_deal` и
   `crm_deal_stage_history`, два запроса на страницу, разбор в PHP.
   - Группы: **в работе** — семантика P, кроме `Suspended`; **отвалились** — F и `Suspended` («пауза = отвалились»);
     **закончились** — S. Пустое `stage_name` в истории восстанавливается по `stage_id`.
   - Сделки менеджеров `DashboardDataService::EXCLUDED_MANAGERS` (191, 195) не учитываются, как в воронке (v40).
   - `cohort(year, at, by_manager)` — сделки, созданные в году. `at=now` — по текущей стадии; `at=year_end` — по
     последней записи истории не позже 31.12 23:59:59 (для текущего года — на сейчас); сделка без истории — по
     текущей стадии. Итог: всего, в работе, отвалились, закончились с долями.
   - `movements(year, by_manager)` — по всем сделкам: сколько за год перешли в «отвалились» и в «закончились».
     Переход — запись истории, группа которой отличается от предыдущей; сделка считается один раз на группу (по
     первому переходу в году). Разбивка «из запросов этого года / прошлых лет». Отмена после паузы — не новый
     переход (группа та же).
   - `gantt(year)` — данные диаграммы (см. ниже).
2. **Страница**. В шапке справа от заголовка — селект года (от года первой сделки до текущего) и переключатель
   «Сейчас / На конец года» (GET-ссылки), пояснение — во всплывающей подсказке у иконки «i»; для текущего года на
   срезе «на конец года» у заголовка бейдж «снимок на сегодня». Крошки «Главная › Движение сделок», вкладка браузера —
   «OSMO CRM: Движение сделок». Под шапкой — вкладки **«Таблица» / «Диаграмма»** (`?view=table|gantt`, по умолчанию
   table; переключение без перезагрузки через `history.replaceState`; смена года и среза сохраняет `view`).
   - «Таблица»: «Новые запросы {год}» (4 плитки), «Движения за {год}» (2 плитки с разбивкой), **администратору**
     (`is_admin()`) — таблица «По менеджерам» с итоговой строкой; остальным разбивка не считается и не выводится.
   - «Диаграмма»: диаграмма Ганта (ниже).
3. **Меню** — пункт «Движение сделок» в разделе «Работа» после «Воронки продаж» (SQL ниже, меню хранится в БД).
   Кнопок-переходов между воронкой и отчётом нет, `index.blade.php` воронки не менялся. Активный пункт меню
   сайдбар определяет по точному совпадению пути (`themes/metronic/components/sidebar/menu-item.blade.php`), поэтому
   на `/bitrix/movement` подсвечивается только «Движение сделок».

## Диаграмма Ганта

- **Отбор сделок года**: в году был переход (начало отрезка стадии в году) или хотя бы день в группе «в работе»
  (P, не Suspended). Сделка, весь год простоявшая в Suspended / F / S, не попадает («пауза = отвалились»).
  Сделок (все / новые запросы года): **2024 — 116 / 116, 2025 — 248 / 179, 2026 — 178 / 112**.
- **Данные** — `DealMovementService::gantt(year)`, одним JSON в страницу (`@json`, без AJAX; ~130 КБ). Отрезки отдаются
  целиком, без обрезки годом (обрезка — в JS для режима «Только год»). Отрезок стадии — от записи
  `crm_deal_stage_history` до следующей (подряд идущие записи одной стадии склеиваются); последняя запись S/F —
  нулевой отрезок «метка конца», иначе — до сегодня. Сделка без истории — один отрезок от `crm_deal.date_create` по
  текущей стадии. Правила групп, исключение менеджеров и восстановление пустого `stage_name` — общие с отчётом
  (`history()` теперь отдаёт ещё стадию и семантику записи). Стадии без названия, которые не восстановить (`7`,
  `PREPAYMENT_INVOICE`, `UC_40X025`, `UC_A93Y5G`, 13 записей), — «Удалённая стадия (код)», серые.
- **Порядок стадий** — `FunnelTableWidget::STAGES` + `Closing documents`, `Completed`, `Suspended`, `Canceled`
  (`GANTT_STAGES_TAIL`), неизвестные — в конце. **Цвета**: P — контрастный набор `GANTT_FUNNEL_COLORS` по месту в
  воронке (`Lead` — чёрный #1a1a1a, соседние стадии не сливаются); `Suspended` — #f5a524 **бледной штриховкой** (пауза = неактивность),
  F — #e5484d, S — #2fb36b; одинаковые в обеих темах.
- **Вкладки** «Таблица» / «Диаграмма» — «острова»: отдельные плашки с тенью, активная залита основным цветом.
- **Вёрстка** — `_movement_gantt.blade.php` (разметка + свои `@section('styles')`/`@section('js')` с `@parent`),
  vanilla JS, без библиотек. Левая колонка (стрелка разворота, название — ссылка на сделку в Битрикс24, как в реестре
  сделок: своей карточки сделки в портале нет; менеджер и компания) закреплена `position: sticky`. Шапка — месяцы
  (по ширине: «Январь» / «Янв» / «Я» / пусто), номера дней при ширине дня ≥ 18 px; разделители месяцев; красная
  линия «Сегодня». Свёрнуто — одна полоса из отрезков (подсказка «Стадия: с … по …, N дн.»), итог S/F — круглая
  метка. Развёрнуто — строка на стадию в порядке первого посещения (повторные заходы — в той же строке), слева —
  стадия и суммарная длительность («<1 дн.» для отрезков внутри дня), между отрезками — SVG-стрелки переходов;
  полоса в строке стадии — 16px (свёрнутая — 14px). Подписи отрезка (11px, ширина текста меряется canvas
  `measureText` тем же шрифтом): если вмещаются «название + отступ + длительность» — внутри полосы название стадии
  слева (полужирное) и длительность справа; если только длительность — она внутри справа; цвет по контрасту
  (на штриховке паузы — тёмный). Иначе длительность снаружи: справа за стрелкой; если упирается в «Сегодня», край
  или соседа — слева от начала; иначе только в title. Пересчёт при зуме. В свёрнутом виде подписей нет.
  Раскрытая сделка обведена линиями 2px сверху и снизу; у двух раскрытых подряд между ними одна линия.
  Общий треугольник слева от «Сделка» в шапке: вправо — все свёрнуты, тире — раскрыта часть (клик раскрывает
  все), вниз — раскрыты все (клик сворачивает). Отрезки соединены «уголками» (clip-path), при наведении — прозрачность 70%. Легенды цветов над диаграммой нет (цвет стадии — слева в развёрнутом виде и
  в подсказке).
- **Период шкалы**: «Только {год}» (по умолчанию; отрезки обрезаются границами года) / «Вся история» (с начала месяца
  самой ранней даты среди **видимых сейчас** сделок — после фильтра попапа, группы и «только новые», но не позже
  1 января выбранного года, год виден всегда целиком; нет видимых — выбранный год; пересчёт при каждом изменении
  фильтров, «Всё» вписывает новый период, левый край прокрутки держит ту же дату; конец — по всем сделкам года,
  конец месяца с последним событием; строка годов над месяцами, выбранный год
  выделен подложкой и пунктиром; при переключении — прокрутка к началу года). Режим — в `localStorage`.
- **Масштаб**: пресеты «Год» («Всё» в режиме истории — весь период вписан в ширину области, пересчёт при resize и
  при первом показе вкладки), «Квартал» (10 px/день), «Месяц» (32 px/день); кнопки «−»/«+» — шаг ×1.5, от «вписать»
  («−» disabled) до 48 px/день («+» disabled). Пресет подсвечен, только если ширина совпала. Центр видимой области
  сохраняется. Масштаб запоминается в `localStorage` отдельно для «Только год» и «Вся история».
  Кнопка «100%» между «−» и «+» подбирает масштаб так, чтобы отрезки видимых сделок заняли ровно экран; срабатывает
  сама при первом показе диаграммы и после каждого изменения фильтра в попапе (решения владельца 16.11).
- **Фильтры**: над диаграммой — «Все / В работе / Отвалились / Закончились» с числами (по выбранному срезу:
  «сейчас» — текущая группа, «на конец года» — на 31.12); «Все сделки года / Только новые запросы года». Клик по
  плитке группы на вкладке «Таблица» открывает «Диаграмму» с этим фильтром; плитка подсвечивается, повторный клик
  снимает фильтр. С «Только новые» числа фильтров совпадают с плитками «Новые запросы».
- **Сортировка** (селект над диаграммой, на клиенте, запоминается в `localStorage`; раскрытые сделки остаются
  раскрытыми). Текущая стадия и группа — на выбранный срез, как у фильтров.
  - «По стадии воронки» (по умолчанию): сначала «в работе» — дальше по воронке выше (место стадии — `funnel` из
    сервиса: `FunnelTableWidget::STAGES` + `Closing documents`), при равной стадии выше тот, кто раньше в неё вошёл;
    затем «закончились» (по дате завершения, свежие выше); затем «отвалились» (по дате перехода, свежие выше).
  - «По дате создания: новые / старые сверху», «По последнему изменению» (`changed` — дата последней записи истории),
    «По длительности сделки» (от создания до итога или до сегодня), «По менеджеру» (строки-заголовки с именем и числом
    сделок, внутри — как «по стадии воронки»).
- **Фильтр в попапе** (решение владельца 16.11; `_movement_gantt_filter.blade.php`). Кнопка «Фильтр» в панели, рядом
  бейдж с числом условий и «Сбросить». Модалка Bootstrap в разметке страницы (перенесена в `body`), фильтр
  клиентский — по JSON диаграммы, сервер не нужен. На телефоне — на весь экран (`modal-fullscreen-sm-down`).
  - «Стадии в сделке» — мультивыбор стадий из данных (цветные точки), «любая из выбранных / все выбранные».
  - «Менеджер», «Партнёр» (компания сделки, как фильтр «Партнёр» реестра v41; пункт «партнёр не указан», поиск).
    Мультивыборы — select2 из `plugins.bundle` (`dropdownParent` — модалка), без него — обычный `select multiple`.
  - «Длительность стадии» — условия [стадия] [от] [до] через «+ условие»; пустая граница — без границы, обе
    включительно («Lead больше 10 дн.» = от 11). Длительность — сумма дней сделки в стадии за всю историю (все
    заходы, открытая стадия — до сегодня, меньше дня = 0); сделка без стадии условию не удовлетворяет. Все условия —
    через И, и с группой / «Только новые»: числа на кнопках групп и «N из M сделок» считают с фильтром.
  - Под панелью — плашки условий («Менеджер: …», «TCP: 20–40 дн.», «Lead: от 11 дн.») с крестиком.
  - Состояние — `localStorage` `deal_movement_gantt_filter`; значения, которых нет в данных года, молча отбрасываются.
  - Диаграмма отдаёт фильтру `window.MovementGantt {data, stages, setFilter(fn)}`. Скрипт фильтра стартует по
    `DOMContentLoaded`: дописываемые секции Blade ставят его раньше скрипта диаграммы.
