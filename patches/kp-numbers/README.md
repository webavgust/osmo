# Сверка чисел КП в PDF и Excel

Стенд прогоняет каждое КП базы через оба шаблона PDF и оба шаблона Excel и сверяет
показанные числа с пересчётом позиций по формулам карточки
(`ProposalRepository::create_variants_new`). Запускать после любой правки
шаблонов `generate/pdf*.blade.php`, `ProposalExcelService`, `ProposalFigures`
или расчёта КП. Работает на локальной базе, в неё ничего не пишет.

## Запуск

Из корня проекта, PHP 8.2.5:

```
php artisan view:clear
php patches/kp-numbers/run.php --jobs=10
python -X utf8 patches/kp-numbers/summary.py storage/logs/kp-numbers.jsonl 2025-06-01
```

Около минуты на 440 КП × 2 шаблона. Второй аргумент `summary.py` — дата, с которой
КП считаются свежими (отдельная колонка). Разбивка категории по месту в документе
с примерами:

```
python -X utf8 patches/kp-numbers/refine.py storage/logs/kp-numbers.jsonl 2025-06-01 "PDF клиент" --ex
```

Таблица «было → стало» по всем расхождениям: сохранить прогон до правки
(`--out=до.jsonl`), после правки прогнать с `--seen` (записывает каждое сверенное
число документа) и собрать Excel:

```
php patches/kp-numbers/run.php --jobs=10 --seen --out=после.jsonl
php patches/kp-numbers/table.php до.jsonl после.jsonl ошибки.xlsx
```

Одно КП: `php patches/kp-numbers/worker.php {id} {default|client_discount} --dump`.
Готовый HTML документа: `php patches/kp-numbers/render.php {id} {шаблон} файл.html [ru|en]`.
Позиции и итоги КП по номеру: `php patches/kp-numbers/dumpv.php AA801 [редакция]`.

## Что считается правильным

- Строка документа — точное значение, округлённое вниз или вверх. Сумма строк
  блока и ИТОГО сверяются строго, ИТОГО — с хранимыми итогами карточки.
- «По умолчанию» (PDF и Excel) — цены после всех скидок.
- PDF «Со скидкой клиента» — строки либо в ценах заказчика, либо партнёрские, без
  смешения. Сейчас партнёрские; это отмечается одной находкой на вариант
  («приложение в ценах партнёра»), пока владелец не решил.
- Excel «Со скидкой клиента» — цены заказчика, НДС с них же.
- Неактивные (жёлтые) позиции видны, но ни в один итог не входят.
- Рубли выводятся целыми, валюта — с центами.

## Как читать результат (29.09.2026)

После правок 29.09 в КП с 2025-06-01 находок нет, кроме «приложение в ценах
партнёра» (вопрос владельцу). Остальное — старые данные до 2025-06: хранимые
итоги не сходятся с позициями, НДС по старой формуле, итоги валютных КП
округлены по отдельности. Категории «КП | …» — про данные в базе, а не про
документы: например, «цена сценария хранится в целых рублях» документы больше
не используют.

Параллельный прогон изредка теряет таблицы (рендер под нагрузкой); такие
прогоны `run.php` сам перепроверяет по одному (`"retried": true` в JSONL).
