# Проект: миграция Laravel-портала osmo на Metronic 8.2.1

Репозиторий: `webavgust/osmo`, ветка `master`. Подробности синхронизации — в `github.md`.

## Правила работы

**Новый модуль обязательно прописывается в `config/modular.php`** — в секцию
`modules.Pub` (или `Admin` / `Bitrix` по принадлежности). Без этого маршруты
модуля не подхватываются. В патч всегда кладётся обновлённый `config/modular.php`
либо явная строчка в README о том, что нужно дописать.

**Патчи нумеруются подряд** (`patch-v9`, `patch-v10`, …), каждый ставится поверх
предыдущих. В каждом патче — README с описанием правок, списком файлов, тем что
нужно сделать руками, и чек-листом проверки.

**Шаблоны кладутся в тему Metronic** — `resources/views/themes/metronic/...`,
а не в `resources/views/...`. Проект работает на теме, файлы в корне не
подхватываются. Исключение — общие Blade-компоненты
(`resources/views/components/`), они одни на обе темы.

**Скрипты и стили страницы** — в `@section('js') @parent` и
`@section('styles') @parent` (так устроен `layouts/layout.blade.php`),
не в `@section('scripts')`.

**Правки вносятся точечно.** Замена файла целиком — только если менялось
большинство его содержимого. Существующая вёрстка, отступы и вокабуляр не
переделываются без запроса.

## Вокабуляр проекта

- Blade-компоненты: `<x-ui.icon.regular>`, `<x-ui.a.box>`, `<x-ui.badge.light>`,
  `<x-proposal.*>`; попапы открываются через `box({href: '...'})`.
- Тостеры: `toastr.success(..., "Это успех!")`, `toastr.error(..., "Это провал!")`.
- Блокировка страницы: `body_block()` / `body_unblock()`.
- Суммы выводятся через `tools()->cost_normalize()`.
- Иконки: в старой теме `fas fa-*`, в Metronic — Font Awesome Pro `fa-light fa-*`.
  В общих компонентах (`resources/views/components/`) использовать `fas` —
  он работает в обеих темах.
- Комментарии в коде на русском, phpDoc у публичных методов.

## Локальная работа (Claude Code)

- **Текущая работа идёт по `patches/PLAN.md`** — план итераций по ТЗ от
  2026-09-09 (v21–v26), факты о данных и принятые решения. Читать в начале
  каждой итерации, по завершении обновлять таблицу «Статус».
- **Тяжёлые задачи делегировать агентам** (Agent tool): реализацию модуля,
  большие правки вёрстки, сбор патча. Самому — разведка, план, точечные правки,
  проверка результата.
- Патчи лежат в `patches/` (`patches/1` … `patches/patch-v20`). Каталог `!patches/` —
  старая копия первого патча.
- Каталог `/public` в `.gitignore`, поэтому правки в `public/metronic/**`
  в git не попадают и живут только в патчах и на диске.
- **Виджеты рабочего стола (patch v30): после любой правки виджета — прогон по всей
  сетке** 2…16 × 2…32 с шагом 2: `php patches/patch-v30/tools/widget_grid.php {id}`.
  В матрице не должно быть кодов X, C, H, F, G; многоточие — только на второстепенном
  тексте; крупные размеры не пустуют. Соглашение и коды — `patches/patch-v30/WIDGETS.md`.
